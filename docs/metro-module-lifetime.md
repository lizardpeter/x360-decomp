# Native module lifetime corrections

Three Metro profile overlays occupy the same original guest image base. A failed load must never consume that range permanently or release a different module's reservation. The pinned SDK marked an XEX loaded before acquiring memory, used a default destructor, and did not release the local partially decoded image when Load failed. It also left a recompiled module wired if AddUser rejected registration, and omitted guest header ownership cleanup. The new independently staged patch tracks only successful allocations, rolls back invalid images and PE parse failures, clears stale metadata, guards short module inputs and releases owned guest headers and native registrations. Synthetic guest-thread regressions exercise repeated malformed loads, collisions, destruction, invalid PE and valid reload; the SDK's existing native module tests remain part of the gate. This is not enabled in production until the native regression passes.
