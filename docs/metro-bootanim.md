# Original 17559 boot animation

The exact verified flash bootanim.xex is already staged by the dashboard runtime builder; the current hosted path does not execute it. It is a distinct 624 KiB decoded XEX with 661 PDATA functions, 104 callable kernel imports and 10 data imports. Its 137,560-byte RIFF audio resource is pinned. It has no XEX entry-point header; the PE parser's default base 0x98000000 is not a callable function (the executable section starts at 0x9800E000). Do not invoke the image base or invent a startup signature.

The original imports include VdInitializeEngines, VdInitializeRingBuffer, VdSwap, VdPersistDisplay, XAudioRegisterRenderDriverClient, XAudioSubmitRenderDriverFrame and XMA context APIs. This is evidence of native graphics/audio work rather than proof of an encoded video. The independent audit establishes exact export roots, module flags, graphics/audio and loader call arguments, stub coverage and RIFF format/chunks. It also looks for original dashboard/XAM references to bootanim. No original bytes are published. Kernel-side invocation is not necessarily present in XAM or dashboard; lack of a reference cannot establish absence of a boot service.

Next integration gates: identify actual export signatures and owner/lifecycle; generate a separate native module from verified callable roots (never use the base as an entry point); validate native graphics/audio contracts; capture rendered original startup frames and actual audio; hand ownership to the dashboard without resetting active native graphics resources incorrectly. Keep the existing direct dashboard path for diagnosis until the animation path is verified. No substitute video or custom animation is used. This is not a full firmware boot claim.

## Startup ABI and embedded XMA1 validation

The original start body at 9800FF08 stores r3 into a guest global, then 9800E448 reloads that same value into r3 for XexGetModuleSection. This proves the first argument is the original module handle. The second argument is a flags word; masks 0x8000 and 0x4000 are tested. The former reaches a display-off branch, the latter contributes to display setup selection. Exact kernel caller policy is not present in the supplied dashboard and XAM images, so no default flag is represented as retail fact. The additional analysis recovers 18 bounded lifecycle helper bodies. The original resource's fmt chunk is XMAWAVEFORMAT with one 12-byte global header and 20-byte descriptors (not PCM/WAVEFORMATEX). Parsing now reports actual stream descriptors, verifies 2048-byte packet alignment and counts seek words. It also matches six original XAM audio routines against the bootanim's static audio library using normalized instruction shapes, including the render-driver registration and callback, to independently identify which bootanim callbacks share the same direct-object ABI. Register operands, memory offsets and comparison values are preserved; only direct branch displacements and lis immediates are normalized. The report distinguishes exact matches from approximate candidates. Reference: FFmpeg n7.1 libavcodec/wmaprodec.c XMAWAVEFORMAT decoder layout. No original code or audio payload is emitted.

### Original clock rejection and native performance

Original arithmetic audit 46062067140 proves 9800FE28 reads the tick count, 9800FE34 subtracts the previous value, 9800FE4C multiplies by the original 0.001 constant, and 9800FE54–9800FE5C discards deltas strictly greater than 0.1 (stores zero rather than clamping). The initial update has corresponding logic at 9800FD20–9800FD28. The graceful gate checks phase +12 against 6.0, nested +196 against zero, phase +36 against 4.5, and the original eligibility/exit bytes. Slow software Vulkan can therefore fail to accumulate animation progress even while the GPU frame counter advances. This remains a hypothesis until measured by the live phase trace. The bootanim module now compiles at O2 separately from other modules. Standalone validation uses the Release SDK configuration. Capture cadence is reduced and the observation budget extended; it never signals, terminates, or changes the guest clock. No original phase constant or instruction is changed. Original event-driven completion remains mandatory.
