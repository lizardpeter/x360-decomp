# Hosted critical-section contracts

The native hosted compatibility layer now supports RtlInitializeCriticalSection, RtlInitializeCriticalSectionAndSpinCount, RtlEnterCriticalSection, RtlTryEnterCriticalSection and RtlLeaveCriticalSection in an explicit single-thread diagnostic mode. The 28-byte record layout and spin count scaling are based on the externally documented compatibility structure in Xenia revision 95a5c3ee250f80c3b9d139658649d9ffb6db3eec (xboxkrnl_rtl.cc), not verified original kernel internals. All guest record fields are read/written big endian, and opaque header/list bytes are preserved. Spin count rounds up and saturates at 255 units. An idle record has lock count -1, recursion 0, owner 0; recursive acquisition and release maintain lock count = recursion - 1. The caller must supply a nonzero aligned diagnostic guest thread identity. A contended try returns false without changing memory; blocking entry, waiter counts, invalid or unknown structures and non-owner release remain unresolved. No scheduler, wait queues, atomic cross-thread access, interrupt semantics, or original-kernel equivalence is claimed. Initialization remains usable without thread identity. Synthetic tests verify spin, recursive acquisition/release, ownership, contention and fault behavior. The original heap startup audit still stops at the unresolved hardware variable, not these later synchronization operations.
