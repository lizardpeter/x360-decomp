# Hosted resource filesystem

The independent native runtime can now mount an explicit immutable resource snapshot and serve original asset bytes through a title-local file handle namespace. Guest paths are never used to open arbitrary host paths. A host-side trusted tree mount snapshots files under a caller-selected volume; symlinks, unsupported nodes, path traversal, duplicate file names after ASCII folding and oversized input are rejected. Snapshot allocation is capped at 512 MiB. The mount is intended for a trusted staged tree that is not concurrently changed.

Implemented export subsets: NtCreateFile/NtOpenFile for existing read-only resources, NtReadFile, NtFlushBuffersFile (no dirty data exists), NtQueryFullAttributesFile, NtQueryInformationFile (basic, index, position, alignment, size and network info), NtSetInformationFile (position only), NtQueryDirectoryFile, and explicit access denial for NtWriteFile. NtClose and NtDuplicateObject route file handles separately from event/semaphore handles, with shared file positions for duplicates. Output ranges and I/O status blocks are validated before consuming file data. Paths are case-insensitive ASCII, with flash: and the observed Device/Flash alias, relative directory handles and bounded wildcard scans. Unknown attributes, access modes, async completions, physical devices, writes, free-space queries and other features are not simulated. Timestamps are unknown (zero) and allocation length is snapshot byte length; no retail FATX parity is asserted. Existing original trace profiles do not enable this service.

This code implements a resource-provider contract, not a reconstruction of the original Xbox kernel filesystem and not the AOT provider. Tests use independently specified bytes. The next integration step is to feed the existing hash-verified staging tree into a native resource probe. No original assets are committed.
