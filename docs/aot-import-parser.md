# ReXGlue 0.11.0 repeated-library record defect

The detailed strict hinted dashboard run 45642145311 reported 7,086 unresolved calls and zero millicode errors. The file-sink and UI reports duplicate entries: 14,172 records, 6,348 distinct (target, site) pairs, 277 distinct targets. Every target is an original xboxkrnl.exe import thunk, independently joined against analysis/dash_17559/imports.tsv. None is an unknown local function. The 30 entry hints and their 37 branch references were independently verified, but cannot correct a missing library record.

Confirmed source defect: rexglue-sdk v0.11.0 revision a3e1d82678ca20d68d4837a8e9ee4652ff073745 src/filesystem/xex.cpp XEXImage::ReadImports uses the name string count as its record count. The hash-pinned retail dash has two strings and three records: XAM 623 slots, XAM 421 slots, kernel 584 slots. The original metadata reader already walks record extents and verifies the complete table. The SDK stops after the second XAM record. The same defect remains in the inspected nightly revision 44b7fdc506ac412bb84b497abad2a3e9026c7173.

The narrow patch changes the SDK loop termination to offset < total, retaining the existing record-length, bounds and name-index checks and positive progress. The original XEX is not changed; no signature, privilege, security or call validation is bypassed. The correction is applied to the exact source revision with a fail-closed source-context check. A separate SDK source build runs strict codegen and, only after success, compiles/links the generated dashboard host. The corrected SDK is not yet tested against the complete original build. The existing XAM host compile/link passed independently (run 45641469939), but guest execution is untested. No original source or executables are uploaded.
