# Hosted XAM file I/O runtime corrections

The first confirmed original-XAM crash is a device-control request for physical IDE pass-through. A file-backed host provider does not offer that hardware service. The new patch removes the host assertion for unsupported control requests, returns a real failure status, and preserves output, IO status and completion state on immediate rejection. It does not execute host ATA commands or return synthetic ATA identification data. The established utility-drive cache geometry remains the same (not a claim of physical console storage geometry). Its two supported operations now validate output size, guest memory access, status-block overlap, event handles and APC context before writing endian-correct data or signaling completion.

The same pinned SDK had two independent file-position defects: an explicit read at offset zero failed to reset an already-advanced cursor, and a positioned write advanced from the old cursor rather than the requested offset. Both now update from the actual transfer offset. Read/write status and offset pointers are checked, ordinary virtual read buffers are validated before the file provider writes, and write input is checked before reading. The existing physical read coherence path is retained. This is native hosted filesystem behavior, not recovered retail kernel code.

Two actual SDK guest-thread regression tests are included, rather than a model of the implementation: unsupported controls, short output, overlapping status buffer, bad event, successful geometry/partition and event completion; then read/seek/write cursor behavior and invalid pointers. The tests are staged in the pinned SDK test suite. The primary boot job keeps tests disabled for build turnaround; a separate SDK test workflow is required to compile and execute them. Source anchor tests run in the primary boot job. The branch omits RelWithDebInfo from the SDK install (Debug host and Release codegen are both still required), with a distinct cache key. The preceding original-XAM experiments remain untouched. No boot outcome or test execution is claimed yet.
