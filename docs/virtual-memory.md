# Hosted guest virtual-memory reservation and commitment

AddressSpace now tracks reservations separately from committed backing storage. Only committed portions are readable/writable. Regular image mappings cannot overlap reserved ranges. Initial supported page sizes are 4 KiB and 64 KiB. First-fit allocation uses bounded guest addresses; commit allocates zeroed pages and rejects overlapping committed regions (recommit is not implemented). Partial decommit preserves unaffected bytes and access permissions; exact-base release removes the complete reserved range and its committed pages. Adjacent committed regions now support atomic cross-region reads and writes. A hole or any read-only destination prevents the entire operation. Page-aligned protection changes on fully committed reserved ranges preserve data and split region metadata transactionally; exported guest protection APIs use a separate restricted adapter described below. Tests cover collisions, overflow, allocation gaps, zeroing, read-only mappings and partial decommit.

The optional hosted NtAllocateVirtualMemory adapter supports the observed dashboard requests: 0x60002000 reserve, 0x60001000 commit, and their combined form 0x60003000, selector zero, PAGE_READWRITE. This is a deliberately limited compatibility model with a deterministic 0x30000000–0x40000000 arena, not original kernel implementation. It validates both output pointers before allocating. It does not support fixed reservations, recommit, general protection/NOZERO, selector 2, or general exported free/protect semantics. The XAM request 0x60803000, size 0x1F0000, selector 2 remains explicitly unsupported; the catalog marks the partial host adapter separately from faithful reconstruction.

Independent local Python reference: the dashboard reserves 1 MiB then commits the first 64 KiB at 0x30000000; it initializes original heap fields and stops at unimplemented subf at 0x92194BC4 after 347 retired instructions (three hosted thunk transitions excluded). Compare trace, integer state, stack, entire loaded image and committed heap digest. Assert the remaining reservation is inaccessible. XAM must stop at the same unresolved allocation call with unchanged baseline state. The prior two startup audit modes remain mandatory. No raw firmware, snapshots, or guest heap contents are published.

## Hosted free and protect boundary

The independent runtime now accepts restricted selector-zero NtFreeVirtualMemory (00DC) and NtProtectVirtualMemory (00E1) calls: aligned 64-KiB decommit, exact-base whole release with zero input size, and read-only/read-write transitions on fully committed reserved pages. The previous first-page protection is reported when requested. Output pointers are validated together and cannot lie in the affected range. Unsupported flags, partial release, unaligned operations, other selectors and allocation arenas are not silently approximated. Interface reference: pinned ReXGlue SDK xboxkrnl_memory.cpp and original import inventory; implementation is a hosted model, not an original kernel reconstruction. Native tests exercise these restricted contracts; the separate AOT host does not consume these adapters yet.
