# Native input: original XAM binding and state reads

The independently decoded 17559 instructions at 8169690C..81696914 construct callback 816D9060 and call the ordinal 020D import thunk. The capability call at 816F1348 passes device context, output structure and a separate DWORD. The state calls at 816F15F8 and 816F28E8 pass context, packet-number output, gamepad output and a separate DWORD. These are verified from the original image, not inferred from the SDK's title-level XInput interface. The older public console driver reference supplies independent evidence that the binding callback takes device identifier, device context, category, disconnect and a byte-sized port pointer.

This branch installs a per-title bridge, registers the actual guest callback, and announces real host-provider pads after XAM attach on the guest main thread. The original binding callback selects the guest port. The kernel's low-level state and capability exports read the existing host input provider, with endian-correct data and checked output ranges. There is no fabricated pad button state or alternate menu. Opaque context IDs are host bridge-owned. The extra DWORD is set to zero for a hosted device with no auxiliary hardware condition; the precise retail interpretation of this output remains to be established. Unsupported device kinds, vibration, hardware LEDs, and hotplug notification/delivery are not implemented by this patch. The bridge is initial enumeration only; no claims about working navigation or live callback success until a real boot proves them.

The regression case validates actual guest export registration and rejection behavior; connected pad state and callback acceptance still require runtime verification. The capture script also fixes the malformed frame-counter expression in its input probe.
