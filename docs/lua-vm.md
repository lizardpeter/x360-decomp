# Authored Lua 5.1 VM core

The prior isolated scalar evaluator and its pinned original-bytecode reference remain unchanged. This new VM adds persistent title globals, raw tables, closures with shared open and closed upvalue cells, fixed and open calls/results, bounded varargs, tail calls, numeric and generic loops, table constructors and assignments, Lua truthiness, scalar arithmetic and coercion. It handles all 38 instruction encodings in the original 5.1 instruction set, subject to the explicit semantic boundaries below. It verifies control flow and operands before execution. Global and closure state persists within a VM instance; numeric object references avoid ownership cycles. The register and instruction budgets apply across nested calls, and tail calls reuse the same depth. No original XAM interpreter body has been recovered; this is a native implementation of the public Lua 5.1 VM contract.

The builtins are deliberately limited to type, tonumber, tostring, next, pairs, ipairs, assert, select and unpack. No OS, file, network, native module loading, unsafe arbitrary callback or metatable behavior is exposed. XUI object userdata and event bindings, coroutines, garbage collection, Lua protected-call/error objects, full Lua locale/number formatting and non-decimal tonumber are not implemented. Sparse table length and iteration order are deterministic hosted choices where Lua does not specify an exact sequence. This is not a hostile-code security sandbox; object arenas are lifetime-bounded by VM instance. Unsupported operations fail explicitly rather than generating fake XUI results.

Tests exercise closures across frame return and CLOSE, upvalue sharing, vararg and multi-result propagation, generic iteration, numeric loops, table identity and deletion, scalar coercion and malformed bytecode. Original dashboard script differential coverage and XAM integration remain separate work.
