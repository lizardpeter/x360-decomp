# Explicit hosted kernel startup adapters

The first three hosted services are XexExecutableModuleHandle (0193), RtlImageXexHeaderField (012B), and ExRegisterTitleTerminateNotification (0015). They are compatibility services, not reconstructed original kernel machine code. The executable handle cell points to a minimal synthetic loader object whose offset 0x58 references the unchanged original XEX header. The original dashboard requests absent field 0x20401; the lookup returns null based on actual header contents. Header lookup supports inline immediate, inline pointer, and header-relative offset forms with bounded original header validation. XAM's actual registration record has callback 0x817399F0 and priority 0x6C000000. Registration is modeled as a local callback registry; invocation, callback ordering and original kernel list mechanics are not implemented. Reference for interface details: Xenia pinned revision 95a5c3ee250f80c3b9d139658649d9ffb6db3eec, xboxkrnl_modules.cc, xboxkrnl_rtl.cc, user_module.cc and xbox.h. No external implementation is copied.

The PPC runner gets an optional provider for exact 32-bit value loads and thunk calls; unknown imports stop as before. Added observed mulli, add, register comparison, stdu and bdnz forms. Reference trace uses synthetic initial registers/stack and hosted service state, not actual console parity. Independent local instruction reference predicts 128 dashboard and 110 XAM retired instructions, stopping at the next unimplemented instructions. Trace, integer state, stack and loaded image hashes are checked. Both pre-provider baseline runs remain mandatory. No import patching, fabricated blanket success, callback execution, scheduler, or dashboard boot.
