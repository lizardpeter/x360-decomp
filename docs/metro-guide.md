The original XAM imports DrvSetSysReqCallback at 0x81A72FF4 (ordinal 0x020C). The existing direct-call census identifies four original callers: 816F0368, 816F0410, 816F0AE0 and 816F0DF0. No private account data or executable payload is emitted. Do not assume a callback ABI or forge a Guide launch.

## First original callback proof

Run 46032021939 succeeded. Five original registration calls were found, four setting the same callback 0x816F09E8 and one clearing it. The original callback forwards its three registers r3/r4/r5 to the common request handler 0x816F06E8 as r4/r5/r6, loading its own object pointer from guest global 0x81AAC260. That handler checks 0x81AAC264 and other original state before posting through 0x816F0368 to KeSetEvent. It also calls original 0x816D8AA8 to resolve the device and user. The worker at 0x816F0AE0 tests Guide-disabled state, permissions and original request fields. Constructor 0x816F0E70 allocates a 36-byte object, publishes 0x81AAC260 and calls 0x816F0DF0; only after that worker is successfully registered does 0x816F0E54 register the original system-request callback. The previous live log has no DrvSetSysReqCallback call, so merely adding the host callback API is insufficient if the original worker never starts. ## Second original lifecycle proof

Run 46032405471 succeeded after correcting the evidence scanner's PDATA tuple unpack. The original public XamInputSendXenonButtonPress tail invokes 0x816F0400, which explicitly sets r5/r6 to zero and posts request type zero to the same original worker. The independent original input message handler 0x816F3C48 passes a real device context from 0x816D8A58 and zero subdevice/type to 0x816F06E8 at 0x816F3E14; the driver callback 0x816F09E8 forwards exactly that tuple. The original device lookup at 0x816D8AA8 scans four guest user groups using the low byte of its subdevice argument and compares the exact opaque device context. Therefore a hosted button event must carry the bound context, subdevice zero and request zero; passing a guest user index as the context would be wrong. The initialization chain contains the original UI initializer 0x816CE8B0 -> 0x816F0F28 -> 0x816F0E70. Six original independently bounded wrappers are explicitly hinted, including callback/worker and public Guide exports. The live trace will identify which stage runs or fails.
