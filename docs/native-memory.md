# Guest memory and native memory-backed functions

The first memory-backed batch covers five distinct 36-byte .pdata entries, representing two original algorithms/register-allocation patterns. They dereference two guest addresses and compare the resulting 32-bit word with an observed constant. The host implementation preserves integer call-state results for successful reads. It deliberately returns an access fault without changing state for invalid reads; this is a host boundary policy, not an emulation of PPC exception side effects. The memory provider rejects overlapping mappings, wraparound, cross-region accesses and writes to read-only regions. These are initial infrastructure contracts, not a complete guest MMU.

Native tests compare each entry with a narrow independent instruction reference over 512 cases. The original audit verifies exact 36-byte original bodies and enumerates all matching .pdata entries. The memory bindings use an explicit separate call signature for now; they are not yet integrated into the integer-only dispatch registry. The earlier 47 entries are promoted to compiles based on successful CI 45541496079; no original-executable differential match is claimed.
