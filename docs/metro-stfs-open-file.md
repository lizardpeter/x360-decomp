# Open-file STFS provider (first implementation)

Original XAM's STFS device creation is not the SDK's existing path-based mount. This patch adds a bounded read-only mount from an already open guest file, using the SDK's existing STFS parser and directory/data extent implementation. It does not reopen arbitrary host paths or assign an account identity. The 64 MiB snapshot limit is deliberate for this initial local-profile reader; large and writable STFS packages need a streaming provider later. The caller must ensure the source is not concurrently modified; size changes and short reads are rejected, but a same-size concurrent write cannot be detected by this layer. Signature/identity validation remains the original caller's responsibility.

The original kernel request structure (88 bytes), object references and command lifecycle must still be connected to this provider after the exact guest ABI is recovered. This isolated workflow tests real fixtures, cross-block reads, read-only access, source-close/delete lifetime, namespace collisions, malformed input and unmount lifetime. It is not enabled in the dashboard runtime until tested.

### Strict open-file snapshot validation

The pinned parser previously emitted warnings for incomplete chains and could publish nodes with out-of-range file extents. For read-only open-file snapshots only, strict parsing now rejects repeated physical blocks, incomplete file/directory chains, invalid header or directory bounds, unsafe names, non-directory parents and excessive nesting. The existing host-path parser remains unchanged. Regression mutations test unsafe names, out-of-range extents, excessive directory count and directory/data overlap without exposing a provider. This is structural validation, not cryptographic authenticity or sign-in.

The strict snapshot mount also rejects duplicate sibling names using the SDK's case-insensitive string keys, so an ambiguous package cannot publish a provider whose enumeration and lookup disagree. Two malformed copies of the existing STFS fixture preserve data chains and change only sibling names (exact and case-only collisions). Existing non-snapshot parsing is unchanged. This is structural validation, not authentication or guest STFS device creation.

### Preserve physical directory slots across deleted entries

The pinned STFS parser used `directory_index + 1` as an index into a compacted vector of parsed nodes, and stopped at the first vacant directory slot. Strict open-file snapshots now scan the whole directory block, map physical table-slot indices to actual parsed nodes, and reject references to absent slots rather than aliasing a later directory. The original host-path parser is unchanged. A native fixture mutation moves a root file into a later vacant slot without modifying its data or other directory references, verifies both the moved file and nested file remain readable, then checks an orphaned child is rejected before a mount is published. This is structural parsing, not signature validation or original guest STFS device registration.
